# 闪电指令（L1 本地声学快速指令）设计

> 状态：待评审
> 日期：2026-08-06
> 范围：设计文档，不含实现代码；实现另走 writing-plans 计划

## 1. 背景与目标

当前 M4 指令通道（长按右 ⇧ / Win+Shift → 录音 → ASR → 词表解析 → 1 秒倒计时 → 模拟按键）的延迟主要来自三处：

1. 云端实时 ASR 的会话建连与流式识别（通常 1~3 秒，建连预算 4 秒）；
2. 必须等松手后的 final 文本才开始解析，流式中间结果只用于展示；
3. 执行前固定 1 秒确认倒计时。

语音控制按三层匹配分层：

- **L1 闪电指令**（本期）：本地声学关键词识别（KWS），高阈值命中即执行，不经过云端 ASR、无确认倒计时；
- **L2 文字匹配**（保留）：现有 ASR 转写 + `command.rs` 词表解析 + 倒计时，兜住闪电词表覆盖不到的指令；
- **L3 大模型匹配**（规划，本期不做）：把指令清单、描述与用户输入交给 LLM 匹配。

## 2. 术语与边界

### 2.1 闪电指令

闪电指令 = L1 本地声学匹配。只在**指令通道录音期间**生效（键盘指令键长按，或唤醒词「小易控」进入的指令录音）。命中高阈值关键词后：

- 立即执行对应按键组合 / 脚本；
- 暂存条短暂展示「已执行」反馈（约 600ms）后隐藏；
- 不显示倒计时、不经过云端 ASR。

保持 PRD 核心原则：**指令语义完全来自指令通道本身**。闪电词表不常驻监听，关闭指令通道后任何语音内容都不会触发指令。

### 2.2 词表范围：只收动作别名

闪电词表只包含**动作别名**（内置 + 用户自定义的 `[[command.action]]`）。其余四类不收：

| 类别 | 是否进闪电 | 原因 |
| --- | --- | --- |
| 动作别名 | 是 | 「说一个短语 = 一个完整动作」，语义完整 |
| 修饰键别名 | 否 | 只是组合键零件，单独说出无可执行动作 |
| 按键别名 | 否 | 既是零件也可能单独成指令（如「回车」），注册后组合场景会被子串抢先触发 |
| 停用词 | 否 | 语义上就是要忽略的填充词；注册成触发词自相矛盾且高频误触 |
| 字母谐音 | 否 | 高频汉字，且只是字母零件，无完整动作 |

KWS 是**子串触发**：若修饰键/按键/谐音也注册，用户说「Shift Command E」时会在「shift」「command」等子串处抢先命中，与 L2 组合键直说冲突。

组合键直说（如「Shift Command E」）是组合式解析、非固定短语，天然留在 L2。

## 3. 运行时架构（并行双轨）

### 3.1 引擎

- 启动 / 配置热加载时构建一个独立的**闪电 KWS 实例**（`LightningSpotter`），复用唤醒词 `model_dir`，与唤醒词引擎分开加载、互不影响；
- 词表 = 所有启用的动作别名（内置 + 用户，已通过唯一性校验保证不重名），每个关键词写入独立的触发阈值后缀（`#0.7`）；
- 唤醒词引擎继续用全局低阈值（默认 0.25），闪电用独立的 `lightning_threshold`（默认 0.7），两者不共享阈值。

### 3.2 录音期双轨

指令通道开始录音时，录音 PCM 扇出两路：

1. 一路照旧喂给云端 ASR 转发器（会话照常建连、边录边传）；
2. 一路喂给闪电识别线程（s16le → f32 转换，按块送入 KWS `OnlineStream`）。

### 3.3 命中流程

闪电命中时：

1. bump 指令代次（`command_gen`），使任何在途 ASR / 倒计时结果失效；
2. 作废并丢弃 ASR 会话与剩余录音；
3. 在主线程调度按键模拟（`injector.simulate_combo`）或脚本执行（`script::run`）——macOS 按键模拟必须走主线程（TSM 断言约束，与现有 Cmd+V / 倒计时执行一致）；
4. 暂存条展示「CMD+C · 已执行」类反馈约 600ms 后隐藏；
5. 一次录音最多命中一次：命中即重置 KWS stream + 置 guard，防止连发。

### 3.4 未命中流程

整句录音结束仍未命中：走现有 L2 流程，**行为与延迟完全不变**（ASR final → `command::parse` → 1 秒倒计时 → 执行）。

### 3.5 录音作废规则

录音期间按下其它键（组合键用法）导致录音被 taint 时，闪电识别同样作废，与现有录音作废语义一致。

### 3.6 降级

- KWS 模型缺失 / 加载失败：闪电整体不可用，L2 照常；
- 某条别名 text2token 转换失败：该条不进闪电词表、仅走 L2，其余条目不受影响；
- 按键模拟 / 脚本执行失败：黄底红字报错（现有异常态语义），不重试 ASR（已作废）。

## 4. 配置

`[command]` 下新增两个字段：

```toml
[command]
lightning_threshold = 0.7      # 闪电关键词统一阈值（默认 0.7，范围 0.3~1.0，步进 0.05）
lightning_disabled = ["复制"]  # 用户关闭闪电的短语列表（内置 + 用户通用）
```

- `lightning_threshold` 写入每条闪电关键词的 `#阈值` 后缀，由 sherpa-onnx 按关键词独立生效；
- `lightning_disabled` 只影响闪电注册，不影响该短语在 L2 文字解析中继续生效；
- 保存后走现有 `runtime-reload` 热加载，无需重启。

## 5. 指令名字唯一性校验

范围：**仅动作别名命名空间**（已定，方案 A）。其他四类保留「用户条目优先、内置兜底」的覆盖语义（例如用户动作别名「回车」允许覆盖内置按键别名「回车」）。

### 5.1 规则

1. 用户动作别名不能与内置动作别名重复（内置 15 条：复制/拷贝/copy/粘贴/黏贴/paste/剪切/cut/撤销/undo/重做/redo/全选/保存/save）；
2. 用户动作别名之间不能重复；
3. 比较前归一化：去首尾空格、全角转半角、ASCII 字母统一小写（`Copy` 与 `copy` 重复，`复制 ` 与 `复制` 重复）；
4. 空短语沿用现有行为（保存时过滤），不参与唯一性判断。

### 5.2 校验位置（两层）

- **前端行内**：动作别名输入框失焦 / 输入时实时校验，重复行标红并提示「与内置指令『复制』重复」或「与已有指令重复」；存在错误时禁止保存。前端需要内置别名清单——由 `get-command-config` 与闪电全量清单一并返回。
- **后端权威**：`save-command-config` 保存前重新校验，发现重复返回带名字的错误、不写盘、不发 `runtime-reload`；`save-config-file`（配置文件兜底编辑器整文件保存）也执行同样校验，防止绕过 UI 直接改 TOML。

## 6. 设置界面

并入现有「语音控制」面板（不新开菜单），保持「一页一菜单、一份数据、一个保存按钮」。

### 6.1 「闪电指令」区块（面板顶部新增）

- **识别阈值**输入框（0.3~1.0，步进 0.05，默认 0.7），带说明：越高越严格、误触越少；
- **全量清单**：内置 + 用户动作别名合并，每行包含：
  - 短语 → 执行动作（组合键展示，如 CMD+C；脚本显示「脚本」）
  - 来源标记（内置 / 自定义）
  - 加载状态（已加载 / 已关闭 / 转换失败仍走文字识别）
  - 开关（内置条目也带开关；内置只能在这里关闭）
- 「查看 Token」调试按钮（沿用唤醒词面板交互）；
- 说明文案：命中即执行、无确认倒计时；闪电只作用于指令通道录音期间。

### 6.2 「动作别名」表格（用户自定义）

- 每行新增「闪电指令」小开关，默认开启；
- 与「闪电指令」区块中对应行**双向联动**：任一侧切换，另一侧立即重渲染；
- 每行新增唯一性行内校验（见第 5 节）。

### 6.3 联动与数据流

- 唯一数据源：`commandConfig.lightningDisabled`（对应 `lightning_disabled` 短语集合）；
- 两个渲染函数（闪电区块、动作别名表格）共用该状态，切换后同时刷新两处；
- `get-command-config` 返回：`config`、`effective_command_countdown_ms`、`builtin_actions`（内置动作别名清单）、`lightning`（全量清单含状态）、`lightning_threshold`；
- `save-command-config` 提交：原有五类词表 + `countdown_ms` + `lightning_disabled` + `lightning_threshold`；
- 残留清理：用户改名 / 删除别名后，`lightning_disabled` 中失效短语在保存时清理。

## 7. 错误处理与降级

| 场景 | 行为 |
| --- | --- |
| KWS 模型缺失 / 加载失败 | 闪电区块显示不可用提示，L2 照常 |
| 单条别名 token 转换失败 | 该条显示「转换失败仍走文字识别」，其余正常 |
| 按键模拟 / 脚本执行失败 | 黄底红字报错，不重试 ASR |
| 指令名字重复 | 前端标红禁存；后端拒绝保存并返回错误 |
| 录音被 taint | 闪电识别作废，与现有录音作废语义一致 |

## 8. 验证清单

- `cargo check` 通过；
- 手动清单：
  1. 指令通道说「复制」→ 本地秒执行 CMD+C，无网络请求、无倒计时；
  2. 说「Shift Command E」→ 仍走 L2，带 1 秒倒计时；
  3. 闪电区块关闭「复制」→ 说「复制」回退 ASR 文字解析 + 倒计时；
  4. 动作别名行开关与闪电区块开关双向联动；
  5. 用户新增动作别名「复制」→ 前端标红、保存被拒；直接改 TOML 保存同样被拒；
  6. 阈值调高后误触减少（灵敏度与准确率可调）；
  7. 唤醒词「小易控」进入的指令录音同样走闪电；
  8. macOS（右 ⇧）与 Windows（Win+Shift）两端都验证；
- 跨平台：KWS 模型已随两平台打包，配置字段平台无关；新增资源无新扩展名，不涉及 CI 上传规则变更。

## 9. 不在本期范围

- L3 大模型匹配；
- 每关键词独立阈值覆盖（本期只有统一 `lightning_threshold`）；
- 闪电命中后的自定义反馈时长 / 样式。

## 10. 已定决策记录

1. L1 采用本地声学关键词匹配（sherpa-onnx KWS），不是 ASR 中间结果匹配；
2. 运行时采用**并行双轨**（方案一）：ASR 与闪电同时跑，闪电命中即作废 ASR，未命中保持 L2 不变；
3. 所有动作别名默认进闪电，允许逐条关闭（内置 + 用户）；
4. 闪电命中无确认倒计时，命中即执行 + 短暂反馈（方案 A）；
5. 唯一性校验范围：仅动作别名命名空间（方案 A）；
6. 术语统一为「闪电指令」（原「快速指令」）。
