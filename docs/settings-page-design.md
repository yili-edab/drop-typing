# drop-typing 设置页面设计

> 状态：设计稿（待评审）
> 日期：2026-08-04
> 范围：仅界面与交互设计，不含实现代码

## 1. 设计目标与原则

- **一页一菜单**：左侧导航固定为 5 个入口，右侧内容区随菜单切换；所有功能不跨页面分散。
- **先常用、后高级**：高频操作（提示词、快捷键、唤醒词、指令词表）平铺展示；低频调参（模型、毫秒、配置文件）收进「高级」模块。
- **兜底可逃生**：任何表单都做不了的事，用户可以打开「配置文件」直接编辑 TOML；保存时必须校验，不能把配置写坏。
- **保存语义统一**：每个面板独立「保存 / 重置」；能热加载的配置保存后立即生效，启动时加载的配置给出明确提示（见 §6）。
- **默认值可恢复**：所有可配置项都有系统默认值，重置按钮恢复到内置默认，而不是清空。

## 2. 整体布局

```
┌──────────────────────────────────────────────────────┐
│ 标题栏：drop-typing 设置                              │
├───────────────┬──────────────────────────────────────┤
│ 左侧导航       │ 右侧内容区（随菜单切换）              │
│               │                                      │
│ · AI 提示词   │  ┌──────────────────────────────┐    │
│ · 快捷键      │  │  当前面板标题 + 帮助文案       │    │
│ · 语音控制    │  │  （表单 / 列表 / 编辑器）      │    │
│ · 语音唤醒    │  └──────────────────────────────┘    │
│ · 高级        │  底部：保存 / 重置等操作按钮           │
│               │                                      │
│ ───────────── │                                      │
│ [重启应用]    │                                      │
└───────────────┴──────────────────────────────────────┘
```

- 窗口：900 × 600，可拉伸，居中，系统装饰（标题栏）。
- 左侧导航底部常驻「重启应用」按钮（警示色），确认后退出并重新拉起应用。
- 右上角 Toast 通知区：保存成功 / 校验失败 / 网络错误。
- 每个面板保存时显示「保存中…」，成功后 Toast；有未保存修改时切换菜单弹确认提示。

## 3. 菜单结构

| 菜单项 | 内容 | 说明 |
|---|---|---|
| AI 提示词 | 基础润色 + 高级润色 | 同一面板内上下两个分区 |
| 快捷键 | 键盘四通道 + 鼠标侧键 | 录制 + 显示当前键位 |
| 语音控制 | Command 指令倒计时 + 指令词表 | M4 指令通道全部配置 |
| 语音唤醒 | 唤醒词开关与关键词列表 + 高级折叠 | 不常用参数收进折叠面板 |
| 高级 | 模型（ASR / LLM）+ 毫秒定义 + 配置文件 | 三个子分区 |

## 4. 面板详细设计

### 4.1 AI 提示词

面板内分上下两个区块，使用分隔线或子 Tab 区分：

**基础润色**

- 文本域（12 行）展示/编辑系统内置通用清洗规则。
- 按钮：`重置`（恢复内置默认）、`保存`、`AI 优化`（弹出意图输入框，调用已配置的 LLM 改写提示词）。
- 帮助文案：修改后点击「保存」生效。

**高级润色**

- 样式 Tab 列表：内置样式（高情商 / 低情商 / 反 PUA / PUA）+ 用户自定义样式；选中后下方文本域（8 行）编辑该样式提示词。
- `+ 添加风格`：输入名称创建自定义样式（禁止与内置重名）。
- 按钮：内置样式为 `重置`，自定义样式为 `删除`（红色，需确认）；另有 `保存`、`AI 优化`。
- 自定义样式删除后不可恢复，删除前弹确认框。

**建议纳入（可选）**

- 面板顶部加一行「当前润色样式」下拉框，与暂存条上的样式选择联动，持久化 `llm.current_style`。这样样式"选哪个 + 内容是什么"都在这一个菜单里闭环。

提示词保存位置：`~/.drop-typing/prompts.json`（不进入 TOML 配置文件）。

### 4.2 快捷键

分「键盘」「鼠标」两个小节：

**键盘**

四行通道，每行由三部分组成：通道名 + 说明、当前键位展示、`录制 / 清除` 按钮。

| 通道 | 说明 |
|---|---|
| 录入（Trigger） | 长按录音，短按提交 |
| 修正（Repair） | 长按说修正指令 |
| 指令（Command） | 长按说按键指令 |
| 取消（Cancel） | 清空暂存条 |

- 点击「录制」进入录制态，展示「正在录制…」；macOS 捕获单键，Windows 捕获修饰键组合；Escape 取消；10 秒无输入自动取消。
- 平台提示文案：macOS 为「单键快捷键（如右 Cmd、右 Opt 等）」，Windows 为「组合快捷键（如 Win + Alt 等）」。

**鼠标**

| 通道 | 下拉选项 |
|---|---|
| 录入（Trigger） | 无 / 前进键（Forward） |
| 修正（Repair） | 无 / 后退键（Back） |

底部按钮：`重置`（恢复平台默认）、`保存`。

### 4.3 语音控制（Command）

**指令确认倒计时**

- 数字输入：`countdown_ms`，默认 1000ms。
- 留空表示沿用全局「高级 → 毫秒定义」中的 `command_countdown_ms`；两者都填时以本面板优先（配置语义与代码一致）。
- 帮助文案：指令解析完成后在暂存条大字展示并倒计时，到 0 自动模拟按键；倒计时期间按任意右修饰键可取消执行。

**指令词表**

五个子分类，每个分类一张可编辑表格，行内支持添加 / 删除：

| 分类 | 列 | 示例 |
|---|---|---|
| 动作别名 | 短语、执行方式（快捷键/执行脚本）、快捷键单字段 + 录制 | 截图 → Shift + Cmd + 4 |
| 修饰键别名 | 短语、修饰键 | win → Cmd |
| 按键别名 | 短语、按键名 | 去除 → DELETE |
| 停用词 | 短语 | 给我 |
| 字母谐音 | 短语、字母 | 挨 → A |

- 动作别名的快捷键通过「录制」按钮直接捕获组合键（修饰键可多选，如 Shift + Cmd + 4），
  单个字段展示，不再手选修饰键与按键。
- 「执行脚本」为预留钩子：选择后填写脚本路径并持久化；当前版本解析到脚本动作时仅提示
  「即将上线」，不会模拟按键，也不会执行脚本。
- 修饰键/按键/字母使用下拉 + 自由输入结合，避免用户手写错格式。
- 帮助文案：未配置任何条目时使用内置词表；用户条目优先匹配，内置兜底。
- 底部按钮：`重置`、`保存`。

### 4.4 语音唤醒

**主区域（常用）**

- 开关：`启用语音唤醒`（`wakeword.enabled`）。
- 关键词列表：每行 = 关键词输入框 + 动作下拉（录入 / 修复 / 指令 / 确认 / 清空）+ `删除`；`+ 添加唤醒词` 按钮。
- 辅助按钮：`查看 Token`（弹出 Token 预览弹窗）、`重置`（恢复内置默认 小易记/小易修/小易控/小易确认/小易清空）、`保存`。
- 帮助文案：保存后需重启应用生效（若实现热加载则改为即时生效提示）。

**高级折叠面板（默认收起）**

使用折叠组件（如 `sl-details`），标题「高级参数」，收纳不常用设置：

| 字段 | 默认值 | 说明 |
|---|---|---|
| 模型目录（model_dir） | 内置模型目录名 | 文本框 + 可选「选择文件夹」 |
| 检测阈值（keywords_threshold） | 0.25 | 越低越灵敏、误触越高，0~1 步进 0.05 |
| 唤醒词 score boost（keywords_score） | 1.0 | 命中分数加成 |
| 静音判定时长（silence_timeout_ms） | 1500 | 唤醒后静音多久判定录音结束 |
| 唤醒词前保留（pre_roll_ms） | 500 | 保留唤醒词前的音频 |
| 环形缓冲时长（ring_buffer_duration_ms） | 3000 | 环形缓冲区大小 |

### 4.5 高级

面板内三个子分区（Tab 或卡片）：模型 / 毫秒定义 / 配置文件。

#### 4.5.1 模型

**ASR（语音识别）**

| 字段 | 控件 | 说明 |
|---|---|---|
| 厂商（provider） | 文本框 | 默认 bailian |
| 协议（protocol） | 下拉 | dashscope-realtime（默认）/ dashscope-http |
| 模型（model） | 文本框 | 默认随协议（fun-asr-realtime / qwen3-asr-flash） |
| Base URL | 文本框 | 留空使用协议默认端点 |
| API Key | 密码框 + 显示切换 | 仅存本地配置，不写入日志 |

辅助：`测试连接`（可选，发起一次最小识别请求验证配置）。

**LLM（文本清洗）**

| 字段 | 控件 | 说明 |
|---|---|---|
| 厂商（provider） | 文本框 | 如 bailian / deepseek |
| 协议（protocol） | 下拉 | openai-chat（默认）/ anthropic-messages |
| 模型（model） | 文本框 | 按可用模型填写 |
| Base URL | 文本框 | 留空使用协议默认端点 |
| API Key | 密码框 + 显示切换 | 不配置 = 关闭清洗、ASR 直出 |
| 优化强度（strength） | 下拉 | conservative（保守）/ standard（标准，默认） |

- 帮助文案明确：不配置 LLM 或 API Key 为空时，清洗层关闭，识别结果直出暂存条。
- API Key 说明文案：仅保存在 `~/.drop-typing.toml` 或环境变量 `DASHSCOPE_API_KEY`，绝不写入仓库。

#### 4.5.2 毫秒定义

| 字段 | 默认值 | 说明 |
|---|---|---|
| 长按判定阈值（long_press_threshold_ms） | 150 | 按住右 ⌘ 达到该时长视为长按录音，否则短按提交 |
| 双击窗口（double_press_window_ms） | 350 | 两次短按松手间隔；该时长内第二击视为双击（清空暂存条） |
| 指令倒计时（command_countdown_ms） | 1000 | 语音指令确认倒计时；被「语音控制」面板的 countdown_ms 覆盖 |

- 数字输入，校验范围建议 50 ~ 10000ms，超出给出行内错误。
- 每项配一句人话说明 + 显示当前生效值（含被覆盖的情况）。

#### 4.5.3 配置文件

作为表单的兜底逃生通道：

- 说明文案：以下为 `~/.drop-typing.toml` 原文，直接编辑并保存；适合表单未覆盖的配置项。
- 等宽字体文本域（约 20 行），显示配置文件原文（**保留全部注释与格式**）。
- 按钮：`重新加载`（丢弃未保存修改，重新读盘）、`保存`。
- 保存流程：
  1. 前端把整段原文发给后端；
  2. 后端先做 TOML 解析校验，失败则返回带行号的错误，**不写盘**；
  3. 校验通过后整文件写回（全文覆盖，不经过结构化序列化，避免丢注释）；
  4. 写盘成功后按 §6 策略应用配置。
- 目标行为：**点保存直接生效**。实现上需要后端提供配置热加载能力；当前启动时加载的配置（热键绑定、唤醒词监听）在热加载完成前，保存后提示「需重启生效」。

## 5. 配置字段映射表

| 面板 | TOML 字段 |
|---|---|
| AI 提示词 | `~/.drop-typing/prompts.json`（base / styles）+ `llm.current_style` |
| 快捷键 | `[hotkey]` trigger / repair / command / cancel；`[hotkey.mouse]` trigger / repair |
| 语音控制 | `[command]` countdown_ms；`[[command.action]]` / `[[command.modifier]]` / `[[command.key]]` / `[[command.stop]]` / `[[command.homophone]]` |
| 语音唤醒 | `[wakeword]` enabled / keywords；高级：model_dir / keywords_threshold / keywords_score / silence_timeout_ms / pre_roll_ms / ring_buffer_duration_ms |
| 高级 → 模型 | `[asr]` provider / protocol / model / base_url / api_key；`[llm]` provider / protocol / model / base_url / api_key / strength |
| 高级 → 毫秒 | `long_press_threshold_ms` / `double_press_window_ms` / `command_countdown_ms`（顶层） |
| 高级 → 配置文件 | `~/.drop-typing.toml` 整文件 |

## 6. 保存与生效策略

- 每个面板独立保存，保存成功后 Toast 提示。
- 配置按加载时机分两类：
  - **运行时可读**：提示词、毫秒参数、ASR/LLM 连接参数——保存后立即生效；
  - **启动时加载**：快捷键绑定、唤醒词监听——当前实现需重启，设计目标改为保存后热加载（重建热键监听 / 重启唤醒词流）。
- 若某阶段未实现热加载，保存后弹窗给出「重启应用」按钮，统一走「重启应用」流程，避免用户困惑。
- 配置文件面板保存成功后，其它面板应重新拉取配置，保证表单显示与实际文件一致（防止双向编辑互相覆盖产生陈旧值）。

## 7. 校验与错误处理

- 数字字段：范围校验 + 行内错误提示。
- API Key：不做格式强校验，仅提示"留空即关闭对应功能"。
- 快捷键：录制时提示暂不支持的键；保存时后端解析失败则回退平台默认值并报错（保持现有行为）。
- TOML 原文：解析失败返回错误行号与原因，不写盘；成功写盘后才提示生效。
- 所有危险操作（重置、删除样式、覆盖配置文件）先弹确认框。

## 8. 一致性修正建议（随本次设计一起处理）

- 唤醒词内置默认已统一为 小易记/小易修/小易控/小易确认/小易清空（5 个，动作 input/repair/command/commit/clear），`config.example.toml` 与代码保持一致。
- AGENTS.md 写"长按阈值默认 250ms"，代码与示例均为 150ms——文档需修正，避免界面展示默认值不一致。

## 9. 暂不纳入 / 后续扩展

- **权限引导**（麦克风 / 辅助功能检测 + 一键跳系统设置）：PRD M4 规划项，建议后续单独入口。
- **定制硬件**：现有占位保留，待硬件功能落地再填充。
- **自动确认**（松手 N 秒自动提交，PRD M3）：尚未进入配置文件，后续按新配置项加入「高级 → 毫秒定义」或独立开关。

## 10. 待评审决策点（含推荐）

1. 配置文件保存后：推荐先实现「热加载 + 失败时提示重启」，而非一律强制重启。
2. AI 提示词面板是否纳入「当前润色样式」下拉：推荐纳入，使样式闭环。
3. 模型面板是否做「测试连接」：推荐 ASR 必做（一次最短录音识别），LLM 可后置。
